# Deployment runbook (M6)

The production stack, all free-tier:

| Piece | Host | Notes |
|---|---|---|
| Frontend | **Cloudflare Pages** | static export of `frontend/` — commercial use allowed, unlimited bandwidth |
| Backend API | **Render** (free web service) | Docker; sleeps after ~15 min idle (keep-warm workflow mitigates) |
| Database | **Neon** (free) | 0.5 GB, scale-to-zero; use the **pooled** connection string |
| Attachments | **Cloudflare R2** (free) | 10 GB, no egress fees, S3-compatible |
| Email | **Resend** (free) | 3,000/mo (~100/day); needs a verified sender domain |
| Schedulers | **GitHub Actions** | daily reminders + business-hours keep-warm |

Everything is driven from the repo: `render.yaml` (Render blueprint), `frontend/next.config.ts` (`output: "export"`), and the workflows in `.github/workflows/`.

> Names below (`po-tracker-*`) are suggestions — use whatever you like, just keep them consistent.

---

## 1. Database — Neon

1. Create a project at <https://neon.tech> (region close to where you'll run Render — e.g. US East / Oregon).
2. From the project dashboard, copy the **pooled** connection string (the host ends in `-pooler.<region>.aws.neon.tech`). It looks like:
   `postgresql://user:pass@ep-xxx-pooler.us-east-2.aws.neon.tech/neondb?sslmode=require`
3. SQLAlchemy needs the `+psycopg2` driver tag. The value you'll paste into Render as `DATABASE_URL`:
   `postgresql+psycopg2://user:pass@ep-xxx-pooler.us-east-2.aws.neon.tech/neondb?sslmode=require`

Migrations run automatically on every backend deploy (`start.sh` → `alembic upgrade head`).

---

## 2. Attachments — Cloudflare R2

1. In the Cloudflare dashboard → **R2** → create a bucket, e.g. `po-tracker-attachments`.
2. **R2 → Manage R2 API Tokens → Create API token**, "Object Read & Write", scoped to that bucket. Save:
   - Access Key ID → `S3_ACCESS_KEY_ID`
   - Secret Access Key → `S3_SECRET_ACCESS_KEY`
3. The S3 endpoint is `https://<ACCOUNT_ID>.r2.cloudflarestorage.com` (Account ID is in the R2 overview) → `S3_ENDPOINT_URL`.
4. `S3_BUCKET` = the bucket name; `S3_REGION` stays `auto`.

Attachments are private — the backend streams them to authorized users; the bucket needs no public access.

---

## 3. Email — Resend

1. Sign up at <https://resend.com>.
2. **Domains → Add domain**, add the DNS records it gives you (SPF + DKIM). Wait for "Verified".
   (No domain? You can send from `onboarding@resend.dev` for testing, but real delivery needs a verified domain.)
3. **API Keys → Create** → `RESEND_API_KEY`.
4. `SMTP_FROM_ADDRESS` = an address on the verified domain, e.g. `po-tracker@yourcompany.com`.
5. Decide `REMINDER_ESCALATION_EMAIL` — where overdue lines escalate after 7 days (§14 Q3).

---

## 4. Backend — Render

1. <https://render.com> → **New → Blueprint** → connect the GitHub repo. Render reads `render.yaml` and creates `po-tracker-api`.
2. It prompts for every `sync: false` var. Fill in:

   | Var | Value |
   |---|---|
   | `DATABASE_URL` | the `+psycopg2` pooled string from step 1 |
   | `CORS_ORIGINS` | your Cloudflare Pages URL (step 5) — e.g. `https://po-tracker.pages.dev`. You can come back and set this after step 5. |
   | `FRONTEND_BASE_URL` | same URL |
   | `RESEND_API_KEY`, `SMTP_FROM_ADDRESS`, `REMINDER_ESCALATION_EMAIL` | from step 3 |
   | `S3_BUCKET`, `S3_ENDPOINT_URL`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY` | from step 2 |

   `SECRET_KEY` and `CRON_SECRET` are auto-generated by Render — **copy `CRON_SECRET`'s value** (Environment tab after first deploy), you need it for step 6.
3. Deploy. Watch the logs — `alembic upgrade head` runs, then uvicorn starts. Health check hits `/health`.
4. Note the service URL, e.g. `https://po-tracker-api.onrender.com` → this is `BACKEND_BASE_URL`.
5. Go back and set `CORS_ORIGINS` + `FRONTEND_BASE_URL` once you have the Pages URL, then redeploy.

---

## 5. Frontend — Cloudflare Pages

1. Cloudflare dashboard → **Workers & Pages → Create → Pages → Connect to Git** → the repo.
2. Build settings:
   - **Framework preset:** Next.js (Static HTML Export) — or "None"
   - **Root directory:** `frontend`
   - **Build command:** `npm run build`
   - **Build output directory:** `out`
3. **Environment variables** (Production): `NEXT_PUBLIC_API_BASE_URL` = the Render URL from step 4 (origin only, no `/api/v1`), e.g. `https://po-tracker-api.onrender.com`.
4. Deploy. Note the URL, e.g. `https://po-tracker.pages.dev` — feed it back into Render's `CORS_ORIGINS` and `FRONTEND_BASE_URL` (step 4.5) and redeploy the backend.

`NEXT_PUBLIC_*` is baked at build time, so **redeploy Pages** if you ever change the API URL.

---

## 6. GitHub secrets + enable the schedulers

Repo → **Settings → Secrets and variables → Actions → New repository secret**:

| Secret | Value |
|---|---|
| `BACKEND_BASE_URL` | the Render URL (no trailing slash) |
| `CRON_SECRET` | the exact value Render generated in step 4 |

Then enable the workflows (they no-op safely until now):

```bash
gh workflow enable "Daily PO reminders"
gh workflow enable "Keep backend warm"
```

Test them once by hand:

```bash
gh workflow run "Daily PO reminders"
gh workflow run "Keep backend warm"
gh run watch
```

Adjust the reminder time in `.github/workflows/reminders.yml` (`cron:` is UTC).

---

## 7. First administrator

There's no public sign-up. Create the first admin with a one-off shell on Render
(**Render dashboard → the service → Shell**):

```bash
python -m scripts.seed_admin
```

It prompts for email + password. Every other user is then created from the in-app
**Users** screen.

---

## 8. Smoke test

1. Open the Pages URL → log in as the admin.
2. **Users** → add a staff user. **Alert Thresholds** → confirm they load.
3. **New PO Line** → create one due in a few days, assigned to someone with a real email.
4. Open it → **Upload file** → confirm it uploads, downloads, deletes (this exercises R2).
5. `gh workflow run "Daily PO reminders"` → check the run summary and the recipient's inbox.
6. Dashboard → the new line shows in "Needs attention" with the right colour.

---

## Ongoing

- **Deploys:** push to `master` → Render and Pages both auto-deploy. CI (`ci.yml`) must be green.
- **Cold starts:** the keep-warm workflow covers business hours (UTC 06:00–20:00, Mon–Fri). Outside that, the first request waits ~1 min. To remove entirely: Render → upgrade the service to a paid instance (~$7/mo), then disable `keep-warm`.
- **Costs:** all $0. Watch: Neon 0.5 GB storage, Resend 100 emails/day, GitHub Actions ~1,300 min/month (of 2,000 free for private repos). R2 10 GB and Pages bandwidth are effectively unlimited at this scale.
- **Logs:** Render dashboard (backend), Cloudflare Pages deployment log (frontend build), GitHub Actions (schedulers + CI).
- **Rotating a secret:** change it in Render *and* the matching GitHub secret (`CRON_SECRET`), then redeploy.
