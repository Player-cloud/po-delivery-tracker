# Pre-launch checklist

Things that should be done before real staff (beyond a pilot) depend on the tool.
Grouped by how blocking they are. The "easy hardening" (dependency scanning,
Sentry, login rate-limiting, security headers, password policy, privacy-notice
template) is **already done** — see PRD §M7.

## Must do before external/wider use

- [ ] **Rotate the secrets that passed through the setup chat** — Neon password,
      R2 API token, Resend API key, and `CRON_SECRET`. Update each in Render and,
      for `CRON_SECRET`, the matching GitHub repo secret. `SECRET_KEY` was
      generated by Render and is fine.
- [ ] **Real sending domain** — buy a domain, verify it in Resend (SPF + DKIM +
      DMARC), set `SMTP_FROM_ADDRESS` to an address on it. Until then reminders
      only deliver to the Resend account owner.
- [ ] **Sub-processor DPAs** — accept/sign the standard Data Processing Agreement
      with Neon, Render, Cloudflare, and Resend; list them in the staff privacy
      notice (template in `docs/PRIVACY_NOTICE_TEMPLATE.md`).
- [ ] **Publish the staff privacy notice** (fill in the template) and decide the
      retention periods it references.
- [ ] **Backup + restore runbook** — Neon's free tier has limited
      point-in-time-restore; decide whether that's acceptable or move DB to a paid
      tier. Write down and *test* the restore procedure.
- [ ] **Uptime alerting** — the keep-warm workflow pings `/health` but doesn't
      alert on failure. Add UptimeRobot / Better Stack (free) with an alert
      contact.
- [ ] **Named incident contact** — who gets paged if the DB is down or emails stop.

## Should do

- [ ] **Move off `python-jose`** → `PyJWT`. `python-jose` pulls in `ecdsa`, which
      has an unfixed timing-attack advisory (PYSEC-2026-1325, currently ignored in
      CI). We only use HS256, so real risk is low, but the dependency is stale.
- [ ] **E2E tests** — Playwright: log in → create a PO line → run the reminder →
      assert the email endpoint response. Add to CI.
- [ ] **Load test** — NFR-1 says the dashboard should load <2 s with 5,000 open
      lines. `dashboard_summary` / `attention_lines` compute in Python over all
      visible rows; verify the target holds, or rewrite them as SQL aggregates.
- [ ] **Accessibility audit** — run axe / Lighthouse on every screen; fix
      contrast, focus order, ARIA, keyboard traps. (The redesign builds toward
      this — confirm it landed.)
- [ ] **Tighten the frontend CSP** — `script-src`/`style-src` currently allow
      `'unsafe-inline'` (unavoidable with a static Next export without nonces).
      Revisit if the threat model needs it.
- [ ] **Shorter JWTs + refresh tokens** — access tokens last 60 min with no
      refresh, so users re-login hourly. Add a refresh flow, or a sliding session.
- [ ] **Audit-log the security-relevant events** — logins, role changes,
      threshold edits, user activation/deactivation. Only PO-line writes are
      logged today.
- [ ] **Attachment scanning** — extension + size are checked; add content-type
      sniffing (magic bytes) and, if the risk warrants it, an AV scan on upload.

## Nice to have

- [ ] SSO (Microsoft Entra ID) — was "proposed" in the PRD.
- [ ] Power BI / reporting connection to the database (read-only role).
- [ ] Visual-regression tests on the key screens.
- [ ] Independent penetration test.
- [ ] A staff acceptable-use note (light — it's an internal tool).
